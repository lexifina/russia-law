(ips.pravo.gov.ru) and can be rebuilt from it. The same downloaded texts give the same commit hashes.

## Fetch rate

The system's own web client reads a public JSON API at `http://ips.pravo.gov.ru/api/ips/legislation/`; the
scripts read the same endpoints, with no login (the API answers without one). `ips.pravo.gov.ru` has no robots.txt
(404), so there is no Crawl-delay; publication.pravo.gov.ru's robots.txt names no AI agents. There was no bot
challenge. Requests were made by at most 4 workers, with gzip, about 4 to 5 requests a second; the server answered in
0.3 to 2 s. Failed requests are retried up to 5 times with growing pauses, and failures are cached for a day.
HTTPS to pravo.gov.ru did not connect from the build machine; plain HTTP did.

## Steps

```sh
cd tools/build
python fetch.py catalogue        # .cache/catalogue.json: search by type (Конституция, ФКЗ, Кодекс, ФЗ)
python fetch.py cards            # .cache/cards/<nd>.json: every act's card with its editions
python fetch.py texts            # .cache/text/<nd>/<rdk>.html.gz: every edition's text
python build.py ../../../russia-law-rebuilt --today 2026-10-28
```

`--today` is the cache's retrieval day. It is required: it dates the documentation commit and divides `main` from
`future`, so a rebuild never depends on the day it is run. `--only` restricts the build to some act types or acts.

## Decisions

- **Which acts:** search type Конституция, Федеральный конституционный закон, Кодекс, Федеральный закон in the
  federal base (`c000000000`); acts whose title begins `О внесении изменений`, `О признании утратившими силу` or
  similar are left out as files (they are commit authors).
- **Dates:** an edition's in-force date is its card `date` ("на <date>"). Commits are dated noon Moscow time with
  the offset of that day (hard-coded: +3 with summer +4 to 2010, +4 from 27.03.2011, +3 from 26.10.2014).
- **Units:** an article starts at a heading paragraph (`class="H"` or `"T"`) reading `Статья N`. Part, section and
  chapter headings between articles go to the next article. `Приложение` starts an appendix. Each <p> is one line;
  older fixed-width texts (`class="M"`) are split into paragraphs at indented lines.
- **Normalised away:** whitespace (a text that differs only in whitespace is not a change) and soft hyphens.
- **Order:** by in-force date; on one date, first texts, then the others in the order of the editions they hold.
